# 基础工程交付说明

## 1. 当前技术基线

本轮用户明确授权开始基础工程开发，并确认从 SQLite 切换 MySQL，接入 Redis、MinIO；会话、登录锁定和接口频控仍使用 MySQL 持久保存，Redis 作为可选缓存。已有 MinIO 私有桶为 `yszx-files`。本次不修改三个 Docker 服务中的密码和桶策略。

后端采用 FastAPI 应用工厂、Pydantic Settings、SQLAlchemy metadata 和会话依赖、Alembic、Redis 与 MinIO 客户端。两个前端采用 Vue 3、Vite、TypeScript、Vue Router、Pinia 和按需注册的 Element Plus 组件，使用 npm workspaces 管理。Python 参考版本为 3.13，兼容范围见 pyproject；Node.js 最低 22.12。

## 2. 已实现边界

- 后端：配置读取与本机配置生成；连接资源的生命周期；MySQL UTC 会话和连接池；统一成功/异常响应、参数校验错误和请求标识；存活检查和三项依赖的只读就绪检查；OpenAPI。
- 数据库：24 张表的 MySQL metadata，初始迁移和冻结 SQL 快照；独立保存历史 SQLite 草案；没有物理外键。启动服务不自动迁移，不创建管理员或学习数据。
- 前端：两个可独立构建的应用入口、独立路由及 Pinia 根实例、共享无身份组件和请求封装；真实服务状态展示、错误及重试交互、预留业务模块页、AI 面试占位。
- 工程：锁文件、环境示例、忽略规则、Makefile、静态检查和基础测试。

本节记录初始基础工程边界；管理端认证与页面样式的后续实现见第 7 节。学员注册登录、签名作答令牌、内容管理、判题、错题、学习统计及文件上传尚未实现。页面预留路由不代表已经完成这些功能。当前无登录成功模拟、预置万能账号或虚构业务统计。

## 3. MySQL 物理设计

保留原业务字段语义；主键为 `BIGINT AUTO_INCREMENT`，逻辑 ID 同为 BIGINT，计数/标志为 INTEGER，时间为 UTC `DATETIME(6)`。数据库连接统一设 `+00:00`；将来接口序列化须转换为带 Z 的 ISO 8601，学习日仍按上海自然日计算。

MySQL 不支持原 SQLite 部分唯一索引，因此增加派生列：符合“有效/进行中/待恢复”条件时为 1，否则 NULL；组合唯一索引包含派生列。MySQL 允许唯一键有多个 NULL，从而允许已删除记录重复，限制有效记录唯一。这些派生列不是 API 输入字段。

课程完整链接仍按原字符串去重。为避免长 URL 超出 MySQL 索引字节上限，使用有效链接的 SHA-256 派生键唯一；业务保存完整 URL，不提取 BV、不删参数。重复键时服务端未来须读取已有 URL 做精确比较；哈希碰撞只能报冲突，不能当作相同课程自动合并。数据库字符集 `utf8mb4`，排序规则 `utf8mb4_0900_bin`。

物理字符串长度是基础存储边界：用户名 64、名称/昵称 128、标题 255、密码哈希 255、URL/来源 2048、标识枚举 32、频控动作 64、维度键 128。题干、解析、选项正文为 TEXT。业务表单的精确校验范围将在模块实现前结合这些边界确定，不把列长等同于已确认密码或业务输入规则。

## 4. 开发与验证

按根 README 执行 `make install / configure / migrate` 后分别启动三个进程。当前开发代理仅绑定本机，Vite 的 `/api` 代理目标为 8000。公开基础检查不读写业务数据，依赖不可用时返回 503 和通用服务状态，不暴露连接串或内部异常。

初始迁移只允许空目标库，MySQL DDL 非事务回滚；执行前检查目标，失败时停止并人工检查，不能直接删除库。使用冻结迁移进行回放，不能通过修改已发布的 0001 快照变更既有库。

本轮真实连接和建表只在确认空的本机目标库执行；基础自动化测试使用替身，不依赖现有用户数据。业务开发时应新增独立 MySQL 测试数据库的事务、并发和约束测试。
