# 管理端认证与页面优化

日期：2026-11-10。用户确认优化原截图中的学员首页，同时新增学员登录页面；后端沿用 Python + FastAPI，并将 CLAUDE.md 的 Java/Spring 规范同步为当前技术。

## 页面实现

学员首页使用浅紫背景、品牌双星图形、学习导引和三学科介绍，提供学习路线、题库和登录入口。首页不再将服务连接状态作为产品主体。两端共用 AuthLayout 和表单样式，包含品牌展示区、用户名密码输入、密码显隐、校验反馈及返回入口；窄屏隐藏装饰区，保留表单。学员登录目前仅为界面，提交会明确提示账号服务未开放，不发起管理端登录或模拟成功。

管理端登录提交真实后端；成功后读取当前会话，跳转原目标页面。路由导航重新校验会话，未登录返回登录页；服务不可用时提示连接失败。用户名来自服务端会话。管理员菜单退出先确认，再请求服务端撤销；网络失败提示重试，会话已失效则返回登录页。管理端其他业务页面仍为空页面。

## 初始化与访问

先按 README 完成依赖、配置和迁移，在项目根目录执行 `make init-admin`。终端会询问用户名（默认 admin）和两次密码（8–128 字符，输入不回显）。不存在默认密码；已有有效管理员不会被覆盖。该命令仅初始化管理员，不创建课程或学员。请在自己的终端输入密码。

运行 `make api`、`make portal`、`make admin`，分别打开：

| 页面 | 地址 |
|---|---|
| 学员首页 | http://127.0.0.1:5173/ |
| 学员登录（界面） | http://127.0.0.1:5173/login |
| 管理员登录 | http://127.0.0.1:5174/admin/login |

此前已运行的后端建议 Ctrl+C 后重新执行 `make api`，以使用禁用代理头信任的启动参数。浏览器保留旧样式时刷新即可。

## 认证实现

管理端认证的三个接口及安全参数以 `docs/design/04.API接口设计.md` 的实施补充为准。密码使用 Argon2id，会话使用服务端随机凭据、MySQL 摘要持久保存和 HttpOnly Cookie，不使用浏览器 localStorage 保存凭据。固定会话有效期为7天；后台固定5分钟窗口同一来源IP最多10次登录请求，计数原子写入MySQL。CSRF采用精确Origin与自定义请求头联合校验，不开放跨域通配。本机HTTP Cookie不设Secure；HTTPS部署必须同步修改Cookie及允许来源。

使用现有 admin_user、admin_session、rate_limit_counter 表，没有改动数据库结构或历史迁移。Redis和MinIO不参与本次登录凭据存储。首发为本机使用，公网代理、部署和其他后台接口仍需各自权限验收。
