## 4. 模块关系与核心业务流程

### 4.1 内容体系关系

```
学科 ─┬─ 阶段（一对多）────────→ 题目（挂在阶段下，供题库中心/刷题练习消费）
     │
     └─（方向 = 学科）─────────→ 面试题（按方向归属，供 AI 面试出题）✅ 已确认
B站课程库（独立维护）──多对多──→ 学习路线（引用课程，课程顺序=学习顺序）
学科/阶段 + 已上架题目 + 课程 ──→ 学习路线可引用（路线构成待确认）
```

- 学科 → 阶段：一对多，阶段是题目的挂载层级，也是首页「热门阶段」的来源。
- 学科 ↔ 课程：**多对多关联**（✅ 已确认），供跨学科筛选、统计与路线引用。每门课程同时有唯一归属：一个学科下的一个阶段；其他学科的关联不改变此归属。
- 首发课程表单不设“其他学科”兜底项，必须选择已有学科及其阶段；未能归类的课程暂不录入。路线选择器中的“其他学科课程”仍可用于跨学科引用已有课程。
- 首发阶段完成：阶段至少有一门当前已上架且未逻辑删除的归属课程，学员完成全部符合条件的归属课程分集，且至少完整完成一轮该阶段练习。没有符合条件的归属课程时，即使完成练习也不能判定为已完成。课程只计入其归属阶段；其他学科路线引用该课程，不将其计入引用方阶段完成条件。归属课程因撤销分集或新增未完成分集而回退时，已完成阶段同步回退；课程重新完成且原有阶段练习记录仍满足条件时，阶段自动恢复完成。
- 课程总集数增加时保留原有分集完成记录，没有历史记录的新增分集默认为未完成，按新总数重新计算进度和整课状态；减少时保留超出范围的历史记录但不计入当前进度，集数恢复时原有状态重新生效。分集顺序不变、已有分集不替换，新视频只追加末尾，平台仅维护分集编号。
- 【后续确认】同一学员对同一课程的分集进度跨路线共享；学习日按 `Asia/Shanghai` 自然日计算。课程不展示也不使用 BV 号；按保存的课程链接完全一致去重，不消除参数差异。
- 【后续确认】学科或阶段删除时，其归属阶段下的课程一并逻辑删除；引用课程的其他路线会受影响，操作前提示。恢复时只自动恢复同次操作级联删除的内容；共享课程恢复后，仍有效的其他路线自动重新显示原引用，此前单独移除的引用不恢复。学科名和阶段名恢复冲突时，在旧名称后加“（已恢复）”，仍冲突则追加递增编号。批次内旧课程的链接与有效课程冲突时暂停整个批次恢复，管理员处理后再重试。
- 【后续确认】管理员生成的临时密码使用一次后失效，暂不设时间期限；使用后必须设置新密码。在新密码成功设置前原密码继续有效；临时密码已使用但改密前关闭页面时，可继续使用原密码或联系管理员重新生成。新密码设置成功后，本次改密会话直接进入平台，该学员其他已有会话失效，须重新登录。

### 4.2 核心业务流程

**流程一：内容生产与上架流（管理端）**

```
创建学科/阶段 → 录入课程（课程库）/ 录入题目（新增后直入「待审核」；status=4 草稿为 DB 预留值，当前不启用）
    → 题目提交审核（待审核）→ 审核通过（已上架）/ 驳回（已驳回 status=5，可修改后重新提交→回到待审核）
    → 上架题目被学员端消费；下架后学员端不再展示
面试题：上传 Markdown 文档解析 / 手工录入 / 手动导入 → 主题维护 → 上架供 AI 面试出题
学习路线：选择学科 + 课程（排序）→ 发布 → 学员端展示
```

**流程二：学习训练闭环（学员端）**

```

首发补充：学员中途退出未完成的阶段练习或错题复习时，已提交并判定的单题仍计入总体正确率，错误作答进入错题本；未完成轮次不计入完整练习次数，也不产生学习日。首发允许返回并继续未完成轮次；每位学员最多同时有一轮进行中的练习，新建前须先处理旧轮次。可手动放弃旧轮次，保留已判定作答及错题；全部题目因下架或题目、所属阶段、学科逻辑删除或所属阶段被禁用而不可作答且没有判定作答时系统自动结束为未完成。两种情况均不计完整练习和学习日。

首发练习清单：服务端保存每轮抽到的题目及其提供给学员时的版本标识，用于版本校验和防止重复计分；首发允许恢复未完成轮次，具体恢复和版本校验流程待细化。

首发重复提交：同一轮次同一题重复提交只计一次，并返回首次已保存的判定结果，不重复更新答题数、错误次数或纠正次数；服务端应先验证轮次归属。

首发错题版本：历史错误记录保留答错时的题目及作答快照；重做使用当前已上架版本。题目下架或逻辑删除期间，历史错误记录保留，但暂不可重做。

未移除的已掌握题再次答错时保持已掌握，仅增加累计错误次数；待复习题答错时连续纠正次数归零。移除的错题再次答错时重新显示，保留并增加累计错误次数，连续纠正次数归零并回到待复习，即使移除前已掌握也适用。题目实质修改后重新上架触发重置的规则另行适用。

首发题目修改：已上架题目的题干、选项或标准答案需实质修改时先下架；修改完成并重新核验、上架时，相关错题连续纠正次数归零，历史作答和累计错误次数保留。仅修改解析或内部来源不重置；依连续答对 3 次得出的已掌握状态随纠正次数归零回退。学员已打开但未提交的题目若实质更新并重新上架，旧答案不判分，应提示并重新获取当前已上架版本。

首发练习中题目下架：学员准备提交时题目仍处于下架状态，或题目、所属阶段、学科已逻辑删除或所属阶段已禁用，则从本轮移除该题、减少本轮题数，旧答案不判分；完成其余题目后即可完成本轮。若所有题目均被移除且没有已判定作答，本轮以未完成结束，不计完整练习次数或学习日，提示题目暂不可用。此前已判定作答保留；其他原因导致题目无法获取时的处理待确认。

每次成功上架保存题干、选项与标准答案的比较用指纹；重新上架时仅在最终内容相对上次上架发生变化时重置，编辑后改回原样不重置。首次上架建立比较基线。题型不计入该重置比较指纹，单独修改题型不触发掌握状态重置；旧页面作答仍需独立进行版本与判分安全校验。
选择学科/阶段 → 刷题（顺序/随机；客观题即时判分，简答走 AI 批改）
    → 答错自动归集错题本（按次数自动分级）
    → 错题重做（连续答对 3 次 → 已掌握）
    → 学习路线：查看课程顺序 → 跳转 B 站学习（外部）→ 手动标记分集完成 → 全部分集完成后自动计入已学课程
```

**流程三：AI 面试闭环（学员端）**

```
配置（方向/难度/题量，校验今日剩余次数）→ 面试进行中
    （AI 读题 + 语音识别作答 / 文字作答，每题 5 分钟超时）
    → 逐题 AI 评分 + 整体评价 + 能力分析 → 面试报告
    → 报告留存为面试记录；报告给出补强建议（推荐题目 / 推荐课程 / 再次面试）
```

**流程四：运营管理闭环（管理端）**

```
数据看板监控指标 → 学员管理（详情/禁用）→ 系统管理（用户/角色/权限/设置）
    → 操作日志全程审计
```

### 4.3 模块依赖关系要点

1. **内容管理是学员端数据源**：学习训练消费「已上架题目」，AI 面试消费「面试题库」，路线消费「课程库」；内容管理任何状态变更直接影响学员端可见性。
2. **错题本是学习训练的枢纽**：刷题产出错题，错题重做回灌练习数据，掌握状态反馈学习统计。
3. **AI 面试报告反向驱动学习**：报告补强建议引导学员回到题库/路线/再次面试，形成「练→面→补」循环。
4. **认证与权限横切两端**：管理端权限树决定菜单与操作可见性；学员端独立登录态。
5. **数据统计聚合**：门户首页、个人中心、管理看板、学员详情消费同一批学习/面试统计数据。
