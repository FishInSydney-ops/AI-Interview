## 2. 通用约定（建议）

- 基础路径 `/api/v1`；学员 `/portal`、后台 `/admin`。路径全小写、单词用连字符，JSON 字段用 `snake_case`；ID 为正整数。路径不携带凭据。`GET` 无业务副作用；写入使用 POST/PATCH/PUT/DELETE，删除为逻辑删除或移除，不代表物理删除。
- 请求 `Content-Type: application/json`，响应 UTF-8 JSON。时间均 UTC ISO 8601（如 `2026-11-07T03:00:00Z`）；学习日按 `Asia/Shanghai` 自然日。外链 B 站由浏览器跳转，服务端不承诺拉取视频或验证播放。
- 列表分页：`page` 整数、默认 1、最小 1；`page_size` 整数、默认 20、范围 1–100，超界返回校验错误；筛选缺省不过滤，排序各接口明确，ID 用作并列排序稳定项。列表数据包 `{"items":[],"page":1,"page_size":20,"total":0}`，空列表为 `[]`。
- 公共输入：`id` 正整数；`sort_order` 非负整数（路线课程顺序从 1 起且同路线不重复）；文本不得全空白；本文未给定精确长度上限及密码强度时，**上限待审核**，不应误称已确认。`null` 仅用于明确允许清空的可选字段；PATCH 缺省表示不修改；未知字段建议拒绝。请求数组不允许重复 ID；数组的上限待审核，练习题数上限 10 除外。服务端验证关联存在、状态和归属。
- `PUT` 替换指定子资源的完整集合；`PATCH` 局部更新。错误与权限约定适用于所有接口。`GET` 不修改练习或生成会话；轮次初始化与版本签发如需要写入，使用 POST。

### 2.1 统一响应（候选）

成功：HTTP 200（创建资源 201），`{"code":"OK","message":"成功","data":{},"request_id":"服务端生成的请求标识"}`；无返回数据时 `data:null`，避免与 204 空响应冲突。错误：`{"code":"VALIDATION_ERROR","message":"请求参数无效","data":null,"request_id":"请求标识","details":[{"field":"page_size","reason":"必须在 1 到 100 之间"}]}`。`details` 仅在有安全可公开的字段信息时提供；不输出异常栈、SQL、密码、Cookie 或哈希。客户端同时检查 HTTP 状态和 `code`。

| HTTP | code | 处理 |
|---|---|---|
| 400 | `VALIDATION_ERROR` | 字段、类型、格式或业务输入无效，`details` 指明字段 |
| 401 | `AUTH_REQUIRED` / `INVALID_CREDENTIALS` / `SESSION_EXPIRED` | 未认证、凭据错误或过期；不区分不存在账号与密码错误 |
| 403 | `FORBIDDEN` / `PASSWORD_RESET_REQUIRED` | 跨身份访问或受限会话访问普通资源 |
| 404 | `NOT_FOUND` | 资源不存在或当前用户不可见；不得泄露其他学员数据 |
| 409 | `CONFLICT` / `QUESTION_CHANGED` / `QUESTION_UNAVAILABLE` / `RESTORE_CONFLICT` / `NO_QUESTIONS` / `ACTIVE_PRACTICE_EXISTS` | 唯一性、版本或状态冲突；按具体接口处理 |
| 429 | `RATE_LIMITED` / `ACCOUNT_LOCKED` | 频控或账号锁定；可安全提供 `Retry-After` 秒数；学员连续 5 次密码错误锁定 5 分钟；后台使用独立登录请求频控，同一来源 IP 每 5 分钟最多 10 次，不按账号连续错误次数锁定，使用固定 5 分钟窗口 |
| 500 | `INTERNAL_ERROR` | 通用内部错误；通过 request_id 排查 |
| 503 | `SERVICE_UNAVAILABLE` | 服务临时不可用；允许安全重试，不虚构成功 |

`QUESTION_UNAVAILABLE` 可伴随本轮已提交且持久化的移题状态；错误响应 `data` 默认 null，安全的最新轮次状态通过 GET 查询。版本冲突或其他错误不得误判为作答成功。具体 409 错误发生时的事务副作用见第 5 节；一般校验错误不改变状态。

### 2.2 身份、安全与频控

- 学员和后台账号域独立，分别使用独立 HttpOnly Cookie，服务端以哈希查 MySQL 会话；普通学员和后台登录固定 7 天，临时密码登录为 15 分钟受限改密会话。两端 Cookie 名称、`Path`、`SameSite`、`Secure`、CORS 来源清单及本地 HTTP 部署方式为**待审核方案**；部署不能依赖跨域通配或关闭安全校验。应设计 CSRF 防护（可信 Origin 校验与 CSRF token 等），认证状态改变时轮换凭据、防止会话固定；具体组合和端到端验证待定。
- 学员会话仅访问 `/portal` 的授权资源；后台会话仅访问 `/admin`，互不可替代。游客只访问明确标记 P 的公开查询及登录注册。受限改密会话仅用于获取受限身份、设置新密码、退出；其他操作返回 `PASSWORD_RESET_REQUIRED`。按服务端当前身份确定学员 ID，不接受客户端指定操作对象为其他学员。
- 临时密码由管理员生成并只在生成响应中显示一次；不可记录或缓存明文，响应 `Cache-Control: no-store`。临时密码成功登录后一次性消费；完成改密前原密码仍可用，改密成功原子更新密码、转换当前会话并撤销其他学员会话。敏感响应 `no-store`；登录、注册及临时密码操作应限流，具体范围、窗口和阈值待确认，MySQL 保存计数不能代替并发验证。

### 2.3 共享数据类型与字段规则

本节类型复用于后文；输出字段均为允许暴露的白名单，`?` 表示输出可为 null；输入必选和可选由各接口说明。字符串长度上限待审核。

| 类型 | 字段与含义 |
|---|---|
| `Subject` | `id:int,name:string,icon:string?,description:string?,sort_order:int` |
| `Stage` | `id:int,subject_id:int,name:string,sort_order:int,is_enabled:bool`；学员可额外返回 `is_completed:bool`（服务端计算） |
| `Course` | `id:int,stage_id:int,title:string,course_url:string,total_episodes:int,status:published\|unpublished,cover_url:string?,duration_minutes:int?,description:string?`；只展示完整链接，不展示 BV 号 |
| `Route` | `id:int,subject_id:int,name:string,description:string?,is_enabled:bool` |
| `QuestionPublic` | `id:int,stage_id:int,question_type:single\|multiple\|judgment,difficulty:easy\|medium\|hard,prompt:string`；未作答时不得包含正确答案、解析、内部来源 |

| `OptionAdmin` | `option_order:int,content:string,is_correct:bool`；单选、判断恰好 1 个正确，多选至少 1 个；判断选项数量及上架解析必填与否待确认 |

| `Page<T>` | 第 2 节分页包，`items` 每项类型为 T |

`course_url` 须为合法允许的 URL，合法协议与 B 站限制待确认；去重使用保存后完整字符串严格相等，不做 BV 解析、参数删除或规范化。数据库值可空的 `icon`、`description`、`cover_url`、`duration_minutes`、`explanation`、`reference_source` 可显式传 null 清空。整数 ID 与数据库逻辑关联均由服务端验证。

每名学员最多一轮 `in_progress`，阶段练习和错题复习共用此限制；创建新轮次前须先处理旧轮次。学员可查询并继续或主动放弃旧轮次；全部题目因下架或题目、所属阶段、学科逻辑删除或所属阶段被禁用而不可用且没有任何判定作答时，系统自动结束该轮，不计完整练习和学习日。新建与提交可能非幂等；网络失败后应先查询已保存轮次或结果，不应盲目创建新轮次。服务端对同轮同题提供去重，不要求客户端凭空推断成功。

## 5. 关键事务与状态处理

1. **判分与版本**：先认证、确认轮次和题目所有权，再检查是否已有首次作答；已答返回历史结果。未答则在同一事务内确认当前题目可用、验证令牌对应的展示版本、校验选项并保存作答快照、错题和完成状态。题型变化即使不触发掌握重置，也必须使旧展示不可误判。`last_published_fingerprint` 不含题型且只用于重置掌握，不能作为唯一作答版本标识。已选择服务端签名临时 `presentation_token` 并在提交事务校验轮次归属及当前题目版本；其生成、有效期、密钥轮换及跨标签并发仍需细化。内容改动后改回原样时，单靠内容哈希不能识别旧版本；已确认增加 `question.answer_revision`，与掌握重置指纹分离，题型、题干、选项或标准答案实际变化时事务递增。签发后提交时必须核对令牌中版本与当前版本，版本不同返回 `QUESTION_CHANGED`；其他不可用判断及并发策略仍须验证。
2. **题目不可用与练习完成**：提交时题目下架或因题目、所属阶段、学科逻辑删除或所属阶段被禁用不可作答，事务中标记该清单项移除、减少有效题数，返回 `QUESTION_UNAVAILABLE`；其他题均完成且仍有有效已判定作答时可完成。已从本轮移除的题目即使恢复可用也不重新加入原轮；后续新练习可再次抽取。若该轮全部题目因上述原因不可作答且没有任何已判定作答，系统自动将该轮记为未完成并结束，不计练习和学习日，允许新建轮次。候选实现复用 `abandoned`；其与手动放弃的原因当前无法从数据库区分，页面不应笼统宣称“学员主动放弃”。建议在造成最后一道题不可作答的后台下架、逻辑删除或阶段禁用事务内检查并结束符合条件的轮次；并发时须与判分和轮次创建串行校验。GET 保持只读，不依赖学员再次提交才结束；具体事务与性能须验证。其他不可用原因待确认；并发提交与发布互斥策略须验证。
3. **统计**：正确率 = 全部已判定正确数 / 全部已判定数，包含未完成轮次；完成次数仅 `completed`；学习日按完成时间转上海自然日去重。阶段完成 = 至少一门当前上架且未删除的归属课程、全部该类课程分集完成、至少一次该阶段完整练习。跨学科引用不计入引用方阶段。分集撤销或内容上下架可改变当前计算结果。
4. **删除恢复**：学科/阶段级联事务写删除批次及实际变化条目；恢复只针对本批次内容，若课程链接冲突则整体失败。预览之后内容可能变化，执行须再次核对。父级有效时允许逐项恢复批次中的课程或题目，单项恢复应原子更新对应批次条目；之后整批恢复只处理尚未恢复的条目。可先只恢复学科，再只恢复阶段，然后逐项恢复或整批恢复剩余内容；名称冲突适用既定后缀规则。整批遇冲突只回滚本次事务，不撤销此前已完成的恢复；并发实现待验证。
5. **错题**：首发不提供手动移除错题入口或接口，已掌握题再错仍掌握，累计错误数加一。保留后续扩展规则：若已有移除状态的错题再次答错则重新显示，累计错误数加一、连续纠正归零；该规则不代表首发开放移除。实质改题重新上架按掌握重置指纹处理；历史快照不改写。

**本轮补充确认**：首发错题本不提供移除入口或接口；阶段禁用仅影响其题目及练习，已上架且未删除的所属课程仍可通过学习路线访问并标记分集进度。

**整体评审新增确认**：首发错题掌握仅按连续答对 3 次自动判定，不提供手动掌握；本机同源代理访问；需提供单独删除课程、题目和路线的恢复能力。恢复与批次交互等细节待确认。

**整体评审补充确认**：错题统计卡与高频 Top 3 推迟，首发仅错题列表与复习；题库详情可查当前题目答案和解析，练习展示接口作答前不返回答案。课程、题目、路线恢复时如所属阶段或学科被删除，暂停并提示先恢复父级。题库详情允许游客访问。

> **边界提醒**：题库详情可查答案，因此“练习作答前不暴露答案”只能约束练习接口及页面，不能保证学员无法通过题库详情查询同一题答案；首发未要求考试防作弊。

**整体评审进一步确认**：单独删除的课程、题目、路线恢复为删除前状态；课程删除时保留路线引用但隐藏，恢复后在仍有效路线自动显示；版本校验采用服务端签名临时令牌，并在提交事务中校验轮次归属及当前版本。题目内容改回原样的版本识别仍待确定。

**整体评审补充确认**：`question.answer_revision` 为独立递增作答版本号；影响判分内容发生实际变更时递增，签名令牌绑定版本，避免旧题改回原样后误接受旧页面。

**本轮补充确认**：课程或题目即使由学科/阶段级联删除，父级有效时亦可逐项恢复；学员账号连续 5 次密码错误锁定 5 分钟；后台使用独立登录请求频控而不按账号连续错误次数锁定；游客可查看符合条件的题目详情及解析。

**本轮补充确认**：允许只恢复学科或阶段本身，亦可整批恢复；先单独恢复父级和部分子项后，整批只处理本批次尚未恢复的对象。后台登录使用独立请求频控，不按账号连续失败次数锁定；同一来源 IP 每个固定 5 分钟窗口最多 10 次。

**本轮新增确认**：后台登录同一来源 IP 每 5 分钟最多 10 次，超限返回 429，频控计数持久保存在 MySQL；学员普通登录态修改密码成功时，同一事务撤销尚未使用的临时密码。

**后台登录固定窗口契约（评审细化）**：以 UTC Unix 时间整除 300 秒得到窗口，`window_start_at` 为窗口起点，`expires_at` 为起点加 300 秒，区间左闭右开。每个来源 IP 的后台登录请求均计入（含成功、失败及超限请求）；同窗口前 10 次可进入登录流程，第 11 次及以后返回 429 `RATE_LIMITED`。频控检查与计数更新需原子执行；重启后依据 MySQL 内仍有效窗口继续计数，超限时 `Retry-After` 可返回到窗口结束的剩余秒数并向上取整。固定窗口边界前后可能连续通过多于 10 次，不等同于任意连续 5 分钟限制。来源 IP 如何穿过本机代理、可信代理配置、时间异常及并发行为待实施验证；其他接口频控规则不因此确定。

**本轮新增确认**：首发个人中心使用默认头像，不提供头像上传；课程录入后不允许修改所属阶段。若删除旧课程再重新录入，形成新课程 ID，旧课程记录与分集进度保留在旧 ID 下，不自动迁移；课程链接和关联规则仍须校验。

## 管理端认证实施补充（2026-11-10）

本节更新管理端已落地契约，优先于上文关于后台 Cookie、来源 IP 与并发行为的待定描述；学员认证及其他业务接口仍属设计。

- 已实现 POST `/api/v1/admin/auth/sessions`、GET `/api/v1/admin/auth/session`、DELETE `/api/v1/admin/auth/session`；登录输入 username 为 1–64 字符、password 为 1–128 字符，拒绝额外字段。首个管理员在本机通过 `make init-admin` 交互建立，创建密码为 8–128 字符，无默认密码或公开注册接口。密码使用 Argon2id。
- 登录成功 HTTP 200，data 为 `{expires_at}`；会话查询 HTTP 200，data 为 `{username,expires_at}`；退出 HTTP 200，data 为 null。时间为 UTC ISO 8601（Z）。错误码包括 400 VALIDATION_ERROR、401 INVALID_CREDENTIALS / AUTH_REQUIRED / SESSION_EXPIRED、403 FORBIDDEN、429 RATE_LIMITED；异常保持统一封装及 request_id。
- Cookie 名为 `yszx_admin_session`，Path=/api/v1/admin，HttpOnly，SameSite=Strict，固定有效 604800 秒；本机 HTTP Secure=false，HTTPS 部署须设 ADMIN_COOKIE_SECURE=true。Cookie 不携带 Domain，不在响应 JSON 返回原始凭据；MySQL 仅保存 SHA-256 摘要。重复登录轮换凭据并撤销本浏览器旧会话；退出同时撤销服务端会话并按相同路径清 Cookie。敏感响应 no-store。
- 管理端所有写方法要求精确匹配 ADMIN_ALLOWED_ORIGINS 且 X-Requested-With=XMLHttpRequest。默认来源为 http://127.0.0.1:5174、http://localhost:5174、http://127.0.0.1:8000、http://localhost:8000；不开放 CORS 通配。API 文档手动调试写请求也须带该自定义头。
- Vite 同源代理保留 Origin；后端以 request.client.host 为频控维度，make api 使用 --no-proxy-headers，不采信客户端转发 IP。首发所有代理请求可能共享本机 IP，符合本机单用户部署范围；公网部署须另审可信代理链与用户隔离。
- 每次登录请求先以 MySQL 唯一窗口键原子 upsert 计数，再进行来源、参数、密码检查；成功、失败、无效参数、拒绝来源及超限请求均计数。前 10 次可进入认证流程，之后返回 429 及到窗口末尾的 Retry-After；服务重建不清空窗口。独立 MySQL 测试已验证 20 个并发请求仅 10 次放行及新窗口恢复。
- 当前其余后台业务 API 尚未实现；新增时必须复用服务端会话验证，不能依赖前端路由守卫提供接口权限。
