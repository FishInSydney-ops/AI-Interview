# 云枢智学开发规范（整体评审草案）

> 供审核，不代表已开始开发。现有 `database-rules.md` 与 `api-rules.md` 保持适用；本规范不得覆盖已确认业务规则。采用 Python + FastAPI + SQLAlchemy + MySQL，双 Vue 3 + Vite + TypeScript 前端；具体依赖版本与工具配置实施前固定。

## 1. 工程组织

- 学员端与后台前端分开组织，独立路由、身份状态及构建产物；允许共用无账号状态的纯工具和经验证的组件。后端保持单体，按认证、内容、练习、错题、进度、统计划分模块。目录建议见整体架构文档；不要因建议目录推断目录已存在。
- 请求层负责认证、参数解析、响应及错误映射；业务层负责业务状态、授权和事务边界；持久化层负责存取和数据库约束；禁止仅靠前端校验、把业务规则散落在页面、或让浏览器直接访问 MySQL 文件。
- 后续 AI、短信适配留在边界，首发不接入；模拟数据只能用于原型或明确标记的测试，不作为真实结果。

## 2. 命名、配置及数据

- Python 模块、函数、变量用 `snake_case`，类用 `PascalCase`；TypeScript 类型和组件用 `PascalCase`，变量和函数用 `camelCase`；数据库、JSON 字段 `snake_case`，HTTP 路径遵循 API 文档。命名统一以明确业务含义为先。
- 数据库禁止物理外键，统一自增主键；关联由服务端校验。业务必需唯一性使用唯一约束或索引，涉及多表的校验与写入在同一事务中处理；UTC 固定格式存储，学习日按上海自然日计算。
- 环境相关配置通过配置层注入；数据库文件、密钥、密码、Cookie、临时密码与个人数据不得写入源码、提交历史或日志。生产与测试使用隔离配置；本机文件备份应采用 MySQL 一致性备份方式并演练恢复。签名密钥生命周期、密码哈希算法及轮换策略实施前审核。

## 3. 接口、认证和错误

- 遵守 `api-rules.md` 及 `04.API接口设计.md`：输入服务端校验，成功与失败统一结构，HTTP 状态和业务码一致，日志记录 request_id 与安全上下文，不暴露 SQL、堆栈、凭据或答案。
- 两端独立会话、独立 HttpOnly Cookie；本地通过同源代理访问后端。CSRF 防护、Cookie 属性、可信 Origin、本机绑定地址和代理规则必须形成可验证配置，不依赖前端按钮隐藏实现授权。
- 每个资源请求检查账号域、身份及数据归属；受限改密会话仅允许必要操作。临时密码明文只在创建响应出现一次，敏感响应禁止缓存。
- 判分、快照、错题和轮次完成在一个事务内协调；同轮同题重复提交返回首次判定。签名令牌绑定学员、轮次、题目与递增作答版本，令牌校验、题目状态/版本校验及写入在事务边界内协调；具体锁定、重试和失效策略需验证。

## 4. 测试与交付约定

- 首发实现必须有可重复的自动化测试，独立临时数据库，不连接真实用户数据；业务单元测试覆盖规则，接口集成测试覆盖权限、状态码、序列化及数据库事务，关键用户流程做端到端验证。
- 至少覆盖：同账号域隔离与受限改密；临时密码消费和会话失效；同学员单个进行中轮次；1–9 题与无题；题目下架/删除/禁用；题目更新后改回原样的旧令牌；重复提交和并发；历史快照；连续三次掌握；课程分集撤销/增减；删除恢复、链接冲突及跨路线引用；上海自然日与未完成轮次统计。
- 数据库结构变更须制定迁移与回滚，审核目标、备份和恢复演练；不得将评审 SQL 草案直接用于现存数据库。依赖与工具版本、静态检查命令、CI 流程及验收阈值在开发启动时具体化并评审，不能宣称当前已配置。
- 合并前检查变更范围、接口兼容性、业务事务与必要测试结果；对未覆盖的风险标注边界。构建、测试和异常不得静默失败。

**整体评审本轮确认**：学科和阶段支持仅恢复自身，同时保留整批恢复；按父级顺序恢复后可逐项恢复课程和题目，整批恢复跳过已恢复条目。后台登录使用独立请求频控，不按账号连续密码错误次数锁定；同一来源 IP 每 5 分钟最多 10 次，计数存 MySQL。

**整体评审本轮新增确认**：后台登录同一来源 IP 每 5 分钟最多 10 次，频控计数存 MySQL 并在重启后按窗口继续生效；学员普通登录态改密成功时，撤销该学员尚未使用的临时密码。

**整体评审本轮确认**：后台登录按固定 5 分钟窗口频控，同一来源 IP 每个窗口最多 10 次；请求计数存 MySQL，重启后按窗口继续生效。固定窗口边界处可出现短时突发，来源 IP 与可信代理配置待验证。
